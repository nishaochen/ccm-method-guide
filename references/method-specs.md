## 0. 四法对照表

| 维度 | QCA | CNA | CORA | NCA |
| --- | --- | --- | --- | --- |
| 分析对象 | 单一结果与条件组态间的充分性/必要性 | 多个结果之间的结构关系（因果链、共同原因） | 联合结果 `Y1·Y2` 及其共享条件组态 | 单一条件的必要性程度（瓶颈） |
| 适配结果结构 | R1；R2 可分别建模；**R4 因果链的「理论检验」路线**（复杂中介／两阶段 QCA，见 §1 末） | R4、R5 | R3 | 任意结构下的必要性补充 |
| 最小化方向 | 自上而下（从真值表出发，逐步删冗余） | 自下而上（从单因子出发，逐步组合） | 系统级联合（多输出电路优化） | 不涉及最小化 |
| 数据形态 | 清晰/多值/模糊集（**模糊集为主流**） | 清晰/多值/模糊集 | **仅清晰集与多值集** | 连续/集合均可 |
| 阈值角色 | 一致性仅用于建真值表，覆盖率仅作挑解参考 | 一致性 con 与覆盖度 cov 为**双硬门槛** | `inc_score` 阈值 | 效应量 + p 值 |
| 主要输出 | 复杂解/简约解/中间解 + inclS、PRI、covS、covU | 各结果的最小充分条件集合（msc）；可选 ASF/CSF | 多输出质蕴涵项（MOPI）+ 单输出质蕴涵项 | 天花板线、效应量、瓶颈表 |
| 解释边界 | 不能据单一结果的路径推断跨结果结构，也不能确立中介地位 | 链式充分结构 ≠ 因果效应或完整中介；受排序设定与阈值约束 | 二值化压缩程度信息；共享组态不代表唯一路径；con 不可与 QCA/CNA 直接比较 | 只回答必要性，不回答充分性 |

## 1. QCA（fsQCA）

**分析对象**：单一结果的充分性与必要性组态。

**默认参数（示例口径，需按研究重新论证）**

| 环节 | 设定 | 说明 |
| --- | --- | --- |
| 校准锚点 | P5 / P50 / P95，直接校准法，端点截断为 0.95 / 0.05；**小样本或量表型变量改用理论锚点** | 用分位数而非样本均值，避免极端值牵引锚点；须报告理论或经验依据 |
| 校准稳健性 | 平行跑 P10 / P50 / P90 | 比较核心组态是否变化 |
| 频数阈值 | 1（大样本可提高） | 至少 1 家案例覆盖的真值表行才进入最小化 |
| 充分性一致性 | 分 0.70 / 0.75 / 0.80 三档检验 | 报告三档解是否相同；不同则说明 |
| PRI | ≥ 0.70 | 与一致性阈值同时施加 |
| 报告的解 | 中间解（并说明复杂解、简约解是否与之相同） | 中间解的方向性预期须写清 |
| 0.5 隶属度 | 剔除**结果变量**的 0.5 案例；报告各变量 0.5 案例数 | 直接校准法以中位点锚定 0.5，原始值恰等于 P50 的案例会落在边界上 |
| 边界案例 | 报告真值表实际纳入的案例数 vs 有效样本数 | 部分软件对边界案例的归类存在不确定性，需做「按高状态处理」的对照 |

**代码骨架**

```r
library(QCA)
# ① 校准
df$X <- calibrate(df$X_raw, type = "fuzzy", thresholds = c(p5, p50, p95))
# ② 必要性初检
pof(df, outcome = "Y", conditions = conds, relation = "necessity")
# ③ 真值表
tt <- truthTable(df, outcome = "Y", n.cut = 1, incl.cut = 0.75, pri.cut = 0.70)
# ④ 三解
sol_c <- minimize(tt, details = TRUE)                       # 复杂解
sol_p <- minimize(tt, include = "?", details = TRUE)        # 简约解
sol_i <- minimize(tt, include = "?", dir.exp = "1,1,1,1")   # 中间解（方向性预期）
```

**报告项**：校准锚点及依据、频数阈值、一致性阈值、PRI 标准、逻辑余项处理方式、所报解类型、各路径的 inclS/PRI/covS/covU、总体解指标、0.5 案例处理与真值表边界案例的影响。

**小样本与量表型变量的锚点怎么选**（问卷研究几乎必遇）

- **不要机械套用 P5/P95 作端点。** N = 58 时 P5 与 P95 分别就是第 3 位和第 56 位案例，锚点随抽样剧烈抖动，换个样本结论就可能变。
- **优先用理论锚点**：7 点量表可用「6 / 4 / 2」（偏保守，全隶属点留一格）或「7 / 4 / 1」（用满量程）；
  5 点量表同理用「5 / 3 / 1」或「4.5 / 3 / 1.5」。锚点要能说出理论含义（「4 分代表既不认同也不反对」）。
- **两套锚点并报**：理论锚点作主分析，分位数锚点作敏感性检验，比较核心组态是否变化。
- **⚠️ 一个高频陷阱**：7 点量表的中点恰为 4，若把 P50 当交叉点，样本中位数又正好落在 4 附近，
  会制造出**大量隶属度恰为 0.5 的案例**（本例正是如此）。这类案例在 fsQCA 中必须剔除，
  剔除量一大样本就不够用了——这本身就是应该改用理论锚点的理由。
- 多题项构念先算**维度均值**再校准；不要用 `(x−1)/6` 之类的线性归一化冒充校准（它没有交叉点，不是集合论校准）。
- 全链路的校准口径须一致：条件之间、条件与结果之间不要混用两套锚点方案。

**解释边界**：单结果视角是**扁平**的——所有条件处于同一分析层级。路径里出现 GI 只能说明「GI 是高结果充分组态的一部分」，**不能**据此判断 GI 是否位于前因与结果之间，也不能建立中介或因果链关系。要回答那个问题，必须改变结果关系结构。

**与 R4 因果链的关系（「理论检验」路线）**：QCA 本身是单结果方法，但 R4 因果链下若**理论已明确提出「前因—中介—结果」机制、研究目的是分阶段检验**，仍可在 QCA 框架内分段推进——复杂中介模型（QCA + 回归，先由 QCA 识别通向中介变量的组态、再估中介与直接效应）、两阶段 QCA（把问题拆为两阶段分别建模后再整合）。两条路线的共同特征是**分结果建模、事后拼接**，跨结果的结构冗余与虚假关联仍可能存在，报告时须交代，也不得把分段结果读成完整的中介效应（见 `design-checklist.md` 第八节）。若研究目的是**发现**尚未完全预设的因果结构，应改用 CNA。

## 2. CNA

**分析对象**：多个结果之间的结构关系。技术内核是把 QCA 的建模范式反转：QCA 自上而下（先构造最大充分条件组合、再逐步删除冗余），在含噪数据下并不保证冗余被彻底消除；CNA 自下而上（从单因子的充分性与必要性出发逐步组合），达到阈值的条件组合在逻辑上自动冗余自由——最小化不是算法的独立环节，而是搜索过程的副产品。

**与 QCA 的关键差别**：CNA 把一致性（consistency）与覆盖度（coverage）**同时**作为硬准入标准，权重相等，阈值不达标即「不输出模型」，宁可无解也不冒险。

**排序（ordering）**：CNA 允许研究者依据理论给出变量的大致层级，例如「五项前因 ＜ GI ＜ EP」。
- 作用：**限定算法的搜索空间**，使结果不出现「结果先于原因」的时间倒置。
- **排序本身不是因果识别的证据**，也不能排除共同前因、样本选择或测量误差。报告中必须这样措辞。

**默认参数**

| 参数 | 设定 | 说明 |
| --- | --- | --- |
| `strict` | `TRUE` | 要求解在逻辑上冗余自由 |
| `suff.only` | `TRUE` | 只输出各结果的**最小充分条件集合（msc）**，表中用「→」而非「⇔」 |
| `con` | 0.75（并跑 0.70 / 0.80 看稳健性） | 硬门槛 |
| `cov` | ≥ 0.35 | 硬门槛 |
| 0.5 隶属度 | **可保留**（与 QCA 不同） | 仍应报告数量 |

**代码骨架**

```r
library(cna)
# 结构发现：给定排序，搜索最小充分条件
cna(dat, ordering = "AID < AII < CDR < CER < lnRD < GI < EP",
    strict = TRUE, suff.only = TRUE, con = 0.75, cov = 0.35)
# 稳健阈值：con/cov 在 1→0.7 间系统变动反复跑，用稳健性分数定阈值
frscored_cna(dat, ordering = "...", maxsols = 100, maxstep = c(3,3,9))
# 因果超图
causalHyperGraph(top.model$condition)
```

**关于 ASF / CSF —— 一个容易踩的坑**

- `suff.only = TRUE` 下 CNA **不产出 ASF/CSF**，只产出 msc。这是最常见的设定，正文若讲的是「最小充分条件」，措辞与之一致即可。
- `suff.only = FALSE` 才产出真正的 ASF/CSF。此时：
  - **ASF 常与原 msc 完全同集**，只是把连接符由「→」升为「⇔」（充分式升为充要式）；
  - **CSF 的等价式数量可能极大**（示范数据中出现 78 个等价式），歧义规模过大，无法在正文列举——这也是实践中维持 `suff.only = TRUE`、只报 msc 的现实理由。
- 若确实要报 CSF，须同时报告解的非唯一性（这是 CNA 的固有属性，不是缺陷）。

**输出解读要点**
- 逐结果报告 msc 数量与具体条件，**按链条环节分组**（如「前因→GI」「GI→EP」「前因→EP」），组内按一致性降序。注意「前因→EP」类各行均不含中间结果。
- 同一 msc 中的条件**不分主次**，不要读成核心/边缘。
- 若同时识别出「含中间结果的链式路径」与「不含中间结果的直接路径」，正确表述是**链式结构与直接路径并存的多路径结构**，而不是「稳定的线性中介机制」。
- 若部分 msc 以「中间结果**非高**」为条件，说明该中间结果不是通向末端结果的普遍必经环节——这往往是最有价值的发现。

## 3. CORA

**分析对象**：多个结果必须同步实现时的共享条件组态（复杂效应）。

**技术内核**（三层）：
1. **多输出质蕴涵项（MOPI）**：若干文字之积，它要么是某个输出函数的质蕴涵项，要么是若干输出函数乘积的质蕴涵项。**后一分支是全新的**——共享原因只有在这里才可能成为质蕴涵项。
2. **不可归约系统**：既不能取消 MOPI 中的任何文字，也不能取消系统中的任何 MOPI 而仍保持系统等价。要点是「系统整体不可归约即可，不必每一部分都不可归约」。
3. **解**＝全部不可归约系统的集合。CORA 返回全部不可归约系统而不加压制，并相应地把 QCA/CNA 的「模型歧义」改称**系统歧义**（system ambiguity），理由是歧义规模若不透明，呈现的结果便无法反映数据中实际存在的经验证据。

**它为什么不能被 QCA/CNA 替代**：CNA 逐结果做输出级最小化，共享原因中那些对单个输出看似冗余的条件会被逐一删去。同一条件、同一份数据，**只因冗余的判定层级不同，结论便可能完全相反**。

**默认参数与前置**

| 环节 | 设定 | 说明 |
| --- | --- | --- |
| 数据形态 | 清晰集或多值集 | **不支持模糊集** |
| 二值化切点 | P50（隶属度 ≥ 0.5 记为高；恰为 0.5 归入高状态） | 切点须在正文显式报告 |
| `inc_score` | 0.75（并跑 0.70 / 0.80） | 一致性阈值 |
| 输出设定 | 同时指定个体结果与合取结果 | |

**代码骨架（Python）**

```python
import cora
ctx = cora.OptimizationContext(data, output_labels=["GI", "EP"],
                                input_labels=["AID","AII","CDR","CER","lnRD"],
                                inc_score1=0.75)
# 也可走官方 Colab notebook：初始化 → 选数据 → 指定输入输出 → 设参数 → 算解 → 画 logigram
```

**输出解读要点**
- **多输出质蕴涵项**（同时覆盖两路及以上输出）＝协同实现的组态引擎；**单输出质蕴涵项**只是普通结果模型。
- 「组态内双高比例」＝满足该组态的企业中多路输出同时为高者所占比重（如 68／71＝95.8%，见 `worked-example.md`）。它**既不是覆盖度，也不是一致性指标**，报告中要给出分子、分母与计算对象。
- 单输出组态与多输出组态并存，说明「单一目标的实现」与「多目标的同步实现」不是同一结果结构——能解释某一结果的组合，并不必然构成协同实现的组态基础。
- 质蕴涵项各自覆盖的企业数**可以重叠**，不构成对样本的划分。共享组态是协同实现的一种方式，不是唯一路径或因果机制。
- 一致性指标 `con` 与 fsQCA 的 `inclS`、CNA 的 `con` **不是同一统计口径**，三者不能直接比数值。
- 数据形态约束（仅清晰集/多值集）属于**方法实施的可行性条件**，不改变「结果结构划定方法逻辑适用边界」的判断。

**成熟度提示**：CORA 2022 年才提出，应用主要集中于医学多病共存与心理学多重用药，管理学近于空白——是卡位机会，也意味着审稿人可能不熟悉，报告需更充分。

## 4. NCA

**分析对象**：必要条件的**程度约束**（瓶颈），回答「至少要到什么水平才够」。

**与 QCA 必要性检验的分工**（这一条最常被混淆）：
- QCA 的必要性检验以**集合一致性**判断某一条件是否构成结果的必要集合（`inclN ≥ 0.90` 才可声称）；
- NCA 进一步刻画必要条件对结果的**程度**约束（天花板线、效应量、p 值）。
- 两者回答的问题与操作逻辑并不相同，**不可相互替代**。

**什么时候用**：研究问题中**存在理论上的必要性假设**时。不要因为「某条件反复出现在充分组态里」就把它解释成必要条件——必要与充分是两种不同的逻辑含义。

**代码骨架**

```r
library(NCA)
m <- nca_analysis(df, c("X1","X2","X3"), "Y")
nca_output(m)   # 效应量 + 瓶颈表 + p 值
nca_plot(m)     # 天花板散点图
```

**组合用法**：先 NCA 定位必要瓶颈 → 再把该条件纳入 fsQCA/CNA 做充分性组态分析。这是 NCA 的典型位置，而不是与 QCA/CNA/CORA 相互排斥的替代方法。

## 5. 共同红线

- **条件数**控制在案例数的 **1/4 以内**（`k ≤ N/4`）。超出时优先按理论删除冗余或高度重叠的条件。
- **校准锚点**必须给理论或经验依据，并报告敏感性检验。
- **隶属度恰为 0.5 的案例**：报告数量与处理方式。QCA 剔除结果变量的 0.5 案例；CNA/CORA 可保留；CORA 二值化时须说明 0.5 归入哪一侧。
- **阈值分档报告**，区分「多档稳定出现」与「仅在特定阈值下成立」两类结构。紧贴阈值的一致性要在正文交代其随阈值提高而变化或消失的条件，不宜表述为稳定发现。
- **时间口径自洽**：作条件者与其余条件同期，作结果者滞后于条件；结果合取的两个结果必须同年；因果链才逐层滞后。任何排序都不能排除共同前因、样本选择与测量误差。
- **解的非唯一性**：CNA 须额外报告；CORA 返回全部不可归约系统，规模须透明；QCA 须报告所报解类型。
- **不比较方法优劣**：只有在研究问题、结果关系结构与方法逻辑相互匹配时，方法之间的比较才具有解释意义。
